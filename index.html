구현 방식

총구에서 조준선 위 합류 지점으로 이동한 뒤 조준 방향으로 진행합니다.

02 / BATTLE NPC NAVIGATION

전투 NPC 특수 이동 경로 탐색

접기펼치기

전투 NPC 담당 범위: 특수 이동 경로 탐색 · PathLink 개인 구현 버전 기준

해결할 문제

비용이 0인 포탈 경로까지 비교하고, 반복 계산을 줄이려면?

구현 방식

NavMesh와 포탈·점프패드·점프·낙하를 상위 그래프로 연결합니다. 일반 이동은 NavMesh 길이, 포탈은 0, 다른 특수 이동은 연결 거리를 비용으로 씁니다.

직선거리 추정 없이 Dijkstra로 누적 비용을 비교합니다.

Context별 Link 비용은 정적 캐시로 재사용합니다. 시작·목표 연결은 요청별 추정과 NavMesh 검증을 거쳐 선택 구간의 상세 경로를 만듭니다. Link 등록·해제·Refresh 시 캐시를 무효화하고 필요할 때 재구축합니다.

03 / PORTAL SYSTEM

공간 포탈의 화면과 통과 처리

접기펼치기
해결할 문제

시점에 맞는 출구 화면을 그리고, 포탈 통과는 서버에서 확정하려면?

구현 방식

입구 기준 카메라를 출구 좌표로 옮기고 포탈 경계에 맞춘 비대칭 투영을 계산합니다. SceneCapture 결과를 포탈 표면에 표시합니다.

화면 점유율에 맞춰 해상도를 정합니다. 기본값은 정지 시 초당 5회, 프레임당 최대 2회 촬영입니다. 가까울 때는 갱신 간격만 해제하고 프레임당 상한은 유지합니다.

적용 결과

카메라 위치에 맞춘 출구 화면과 출구 면 클리핑을 구성합니다. 이동은 서버가 확정하며 소유 클라이언트의 예상은 통과 전후 벽 충돌 처리에만 사용합니다.

공간 포탈 렌더링 (새 창)촬영 스케줄링 (새 창)클리핑 투영 행렬 (새 창)클리핑 경계 검증 (새 창)

출구 면을 렌더링 시작 경계로 설정

가상 카메라와 출구 사이의 벽을 잘라냅니다. 카메라 거리는 원근감 계산에 유지하고, 출구 면부터 장면을 그립니다.

BuildWindowProjection()의 깊이 항에 출구 경계를 반영해 CustomProjectionMatrix에 적용합니다. 현재 clipOffset은 0입니다.

Global Clip Plane 전역 설정과 셰이더 재빌드 없이 처리합니다. 테스트는 출구 면 이전·이후 점의 깊이값을 비교합니다.

서버의 이동 확정과 로컬 벽 충돌 처리

서버가 입구 접촉과 통과 방향을 검사하고, 출구 좌표·속도·시점을 변환합니다. 도착 영역과 경로의 충돌을 확인한 뒤 TeleportTo로 이동을 확정합니다. 막힘이나 Capsule 중첩이 있으면 통과를 거부합니다.

출구의 가로 중앙에 도착하며 높이와 속도 크기를 유지합니다. 서버는 이동 확정 후 시점을 전달하고 네트워크 갱신을 요청합니다.

소유 클라이언트는 접근 위치와 속도로 충돌 제외 영역을 예상해 해당 포탈 벽의 이동 충돌을 임시로 제외합니다. 서버 위치가 반영되고 출구를 벗어나면 제외를 해제합니다. 로컬 예상은 벽 충돌 처리에만 사용하며 포탈 이동은 서버에서 확정합니다.

  1. 서버 접촉·방향 검사
  2. 출구 좌표·속도·시점 변환
  3. 도착 영역·경로 충돌 검사
  4. TeleportTo·네트워크 갱신

  2. 등록된 검사 모듈 실행

  4. Focus 대상·시점 이동
