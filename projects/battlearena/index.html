01 / COMBAT SYSTEM

총구와 조준선을 연결하고 이동 구간 전체를 검사

접기 −펼치기 ＋
해결할 문제

총구와 카메라 조준선의 위치 차이를 어떻게 처리하고, 업데이트 사이의 얇은 벽과 플레이어를 빠뜨리지 않고 검사할까?

구현 방식

총구 방향만 사용하면 조준점과 어긋날 수 있어 조준선 위의 합류 지점까지 이동한 뒤 조준선 방향으로 진행합니다. 합류까지의 시간과 프레임의 남은 시간을 나눠 각 방향의 이동을 계산하며, 충돌하면 중단합니다.

RecordTravel로 기록한 각 이동 구간을 Sphere Sweep합니다. 이전 위치 P0와 다음 예정 위치 P1 사이 전체를 검사하고, 가장 이른 Hit.Time을 선택합니다. 플레이어 명중용 큰 Sphere와 환경 충돌용 작은 Sphere의 반경을 분리합니다.

서버는 환경에 SweepSingle, 플레이어에 SweepMulti를 사용합니다. 클라이언트는 환경만 SweepSingle로 검사하고 플레이어 후보 검사를 생략합니다. 플레이어 후보는 서버 권한과 피해 가능 상태를 확인한 뒤 검사하며, Line Trace로 벽 가림도 확인합니다.

적용 결과

합류 전후의 이동 시간을 나눠 처리하고, 이동 구간 전체에서 가장 먼저 닿은 충돌을 선택합니다. 플레이어 판정은 서버에서 검사합니다.

02 / BATTLE NPC NAVIGATION

포탈 비용을 반영한 전투 NPC 경로 탐색

접기 −펼치기 ＋

전투 NPC 담당 범위: 특수 이동 경로 탐색 · PathLink 개인 구현 버전 기준

해결할 문제

포탈 통과 비용이 0인 특수 이동과 일반 NavMesh 경로를 비교하고, 반복 요청의 연결 비용을 어떻게 재사용할까?

구현 방식

NavMesh의 일반 이동과 포탈·점프패드·점프·낙하 연결을 잇는 상위 그래프에서 경로 비용을 비교합니다. 일반 이동은 NavMesh 경로 길이, 포탈 통과는 비용 0, 점프 등 다른 특수 이동은 연결 거리를 반영합니다.

포탈은 먼 위치도 비용 0으로 연결하므로 직선거리 추정이 실제 남은 비용보다 클 수 있습니다. 별도 휴리스틱 없이 Dijkstra로 누적 비용을 비교합니다.

Context별 Link 간 비용은 정적 그래프로 캐시합니다. 시작·목표 연결 비용은 요청별로 추정하고 NavMesh로 검증한 뒤, 선택한 구간의 상세 경로를 생성합니다. Link 등록·해제·Refresh 시 캐시를 무효화하고 필요할 때 재구축합니다.

적용 결과

전투 NPC의 특수 이동 경로에서 일반 이동과 비용 0의 포탈 연결을 함께 비교하고, 정적 그래프와 요청별 연결 비용을 조합합니다.

03 / PORTAL SYSTEM

공간 포탈의 시점·클리핑과 서버 통과 처리

접기 −펼치기 ＋
해결할 문제

가상 카메라와 출구 사이의 벽이 화면을 가리지 않게 하면서, 서버의 이동 확정과 로컬 플레이어의 벽 충돌 처리를 어떻게 연결할까?

구현 방식

입구 기준의 카메라 위치를 출구 좌표로 변환하고, 포탈 경계로 비대칭 투영(Off-axis projection)을 계산합니다. SceneCapture 결과를 포탈 표면에 표시해 보는 위치에 따라 출구 화면이 달라지도록 구성했습니다.

화면 점유율에 맞춰 렌더 타깃 해상도를 선택합니다. 기본 정지 갱신은 초당 5회, 촬영 상한은 프레임당 2회입니다. 새 공간 포탈은 가까울 때 갱신 간격을 생략하되 프레임당 촬영 상한은 유지합니다. 이 수치는 코드 기본값입니다.

  1. 카메라 위치
  2. 입구→출구 좌표 변환
  3. 비대칭 투영 계산
  4. SceneCapture 표면 표시

출구 면을 렌더링 시작 경계로 설정

가상 카메라와 출구 사이에 있는 벽이 포탈 화면을 가리지 않도록 출구 면을 Near Clip 경계로 설정합니다. 가상 카메라의 거리는 원근감 계산에 유지하면서 출구 면 이전의 공간을 잘라냅니다.

BuildWindowProjection()에서 포탈 크기와 카메라 거리로 비대칭 투영을 계산하고 투영 행렬의 깊이 항에 경계를 반영합니다. 현재 clipOffset은 0이며, 출구 면이 렌더링 시작 경계입니다.

계산한 행렬을 SceneCapture의 CustomProjectionMatrix에 적용합니다. Global Clip Plane 전역 설정과 셰이더 재빌드 없이 클리핑을 처리하며, 검증 코드는 출구 면 이전·이후 점의 깊이값을 비교합니다.

  1. 입구→출구 가상 카메라 변환
  2. 투영 행렬에 출구 경계 반영
  3. CustomProjectionMatrix 적용

서버의 이동 확정과 로컬 벽 충돌 처리

서버가 입구 접촉과 통과 방향을 검사하고, 출구 좌표·속도·시점을 변환합니다. 도착 영역과 경로의 충돌을 확인한 뒤 TeleportTo로 이동을 확정합니다. 막힘이나 Capsule 중첩이 있으면 통과를 거부합니다.

출구의 가로 중앙에 도착하며 높이와 속도 크기를 유지합니다. 서버는 이동 확정 후 시점을 전달하고 네트워크 갱신을 요청합니다.

소유 클라이언트는 접근 위치와 속도로 충돌 제외 영역을 예상해 해당 포탈 벽의 이동 충돌을 임시로 제외합니다. 서버 위치가 반영되고 출구를 벗어나면 제외를 해제합니다. 로컬 예상은 벽 충돌 처리에만 사용하며 포탈 이동은 서버에서 확정합니다.

  1. 서버 접촉·방향 검사
  2. 출구 좌표·속도·시점 변환
  3. 도착 영역·경로 충돌 검사
  4. TeleportTo·네트워크 갱신
적용 결과

카메라 위치에 맞춘 출구 화면과 출구 면 클리핑을 구성합니다. 이동은 서버가 확정하며 소유 클라이언트의 예상은 통과 전후 벽 충돌 처리에만 사용합니다.

출구·목적지 누락, 잘못된 연결과 값, 경로 입구의 지면 이격을 오류로 보고합니다. Slate의 Focus 버튼을 누르면 대상 오브젝트를 선택하고 시점을 이동합니다.

  1. 포탈·점프패드·이동 경로
  2. 등록된 검사 모듈 실행

  4. Focus 대상·시점 이동
